Implementation notes
- Filters combine (Segment = Municipality AND Service = Sidewalk Survey). Empty results need a written empty state, not a blank page: “No projects match all three filters. Try removing one, or contact us - the library is a sample of our work, not the whole of it.” That last clause matters and is true.
- Filter state should be URL-encoded (/projects/?segment=dot&service=friction) so a salesperson can send a filtered link to a prospect. This is the single highest-value implementation detail on the page.
- Default view: all projects, most recent first. Never default to a filtered subset.
- Filters must be visible above the fold on mobile, not collapsed behind an icon.
- Each project card should display segment and service as visible tags, so the organizing logic is legible without touching the filters.

3. The challenge. What the agency was facing before. Two or three sentences, specific. “They needed pavement data” is not a challenge; “their last network survey was nine years old and their capital program was being set from complaint volume” is.
4. What ICC-IMS did. Scope, method, equipment, timeline. Concrete and factual.
5. The result. The section that justifies the page. Requires at least one measurable outcome. If no measurable outcome can be confirmed, the project becomes a short project listing rather than a full case study - see Section 5.
6. Testimonial. Where an attributable one exists, with name, title, and agency.
7. Related. Links to the service pages, equipment pages, and audience page for the segment.
8. CTA pair. Low: the relevant service overview or sample report. High: Request a Similar Assessment.
### Writing standards
- Outcome-framed headlines. “How Wyoming DOT improved network data quality,” not “Wyoming DOT.”
- Numbers over adjectives. Every claim that could carry a number should carry one.
- The agency is the protagonist. The agency solved a problem; ICC-IMS supplied the capability. This reads as more credible and is also more accurate.
- No superlatives. Per the site-wide voice convention.
- Client approval before publication. Every case study naming an agency, and every quote, should be approved in writing by that agency. This is standard practice and protects the relationship.
## 3. Two tiers, because fifteen full case studies is optimistic
Realistically, not all fifteen projects will yield a measurable outcome, an approving client, and a project manager with time to reconstruct the details. Planning for fifteen full case studies and delivering six produces a half-empty library.
The recommended structure is two tiers:
Tier 1 - Full case study. Own page, full template, measurable outcome, client approval. Target six to eight, weighted toward segment coverage rather than toward whichever projects are easiest to document.
Tier 2 - Project listing. A card in the filterable library with agency, location, network size, services, equipment, and timeframe - but no dedicated page and no outcome claim. Still filterable, still counts as proof, still carries the agency name.
This matters for the filters. A visitor filtering to Airport and finding one result concludes ICC-IMS has done one airport. Tier 2 listings keep the library populated across every filter combination while the Tier 1 set is built out over time.
Recommended minimum for launch: one Tier 1 case study per segment filter value, with everything else as Tier 2. That guarantees no segment filter returns an empty or single-item result.

## 5. The fifteen project briefs
Each brief lists what is confirmed, what is proposed, and what must be supplied. Proposed classifications are inferences from agency type and available testimonial context - all require confirmation by the project manager.
### Standard intake questions
Run these for every project. Most can be answered in ten minutes by whoever managed it.
- What year, or year range? Is the relationship ongoing?
- Network size - centerline miles, lane miles, or facility count?
- What did the agency have before? Old data, no data, a failing program, a different vendor?
- What specifically was delivered? Services, equipment, software.
- What changed for the agency as a result? The one question that determines Tier 1 or Tier 2.
- Is there a number attached to that change? Funding secured, cost avoided, condition improved, time saved.
- Who at the agency would approve a case study, and would they?
- Are there usable photos?
