# References

Drop visual references here: the concept image, a moodboard, competitor screenshots, sites
the client likes, brand assets. Reference images beat prose for communicating look and feel,
so this folder does a lot of the work of making output custom.

## What to add

- The concept image or sketch, if there is one.
- Screenshots of competitor and reference sites (name them, for example
  `competitor-acme-home.png`).
- The client's existing brand assets (logo, existing site) if any.
- A moodboard image or a few pinned examples.

## How to use references (important)

For each reference, record what you take from it in a short note (in `brief.md` competitor
section, or a caption file):

- **Measured vs inferred.** Say which values you actually measured from the reference (exact
  hex, spacing, type size) and which you are inferring (feeling, general direction). Measured
  values can go straight into `tokens.json`. Inferred ones are direction, not fact.
- **Extract structure, not identity.** Borrow layout logic, rhythm, and system, not a
  competitor's brand. We are learning how a thing is built, not copying who it belongs to.

## Naming

Keep names descriptive: `[source]-[page]-[note].png`. For example
`stripe-pricing-layout.png`, `client-old-site-home.png`. The AI reads these names, so make
them mean something.
